# AI4S 投资 sourcing（AI × 全科学领域 · 全球）

从 OpenAlex 按「科学领域」分批抓取 AI4S 论文 → 规则筛选与分类 → 聚合成人才库 → 评分排序 → 导出 Excel 线索表 + 可视化软件。

覆盖 16 个二级科学领域（分类体系见下文），每个领域取三批：2019 年以来被引最高的 2000 篇、近 2 年被引最高的 1000 篇、近 6 个月最新发表的 1000 篇（按发表时间排，不看被引，保证新人新作不被漏掉）。最新论文每次更新时滚动累积：上次抓到、仍在 6 个月内的会保留，每个领域最多 5000 篇（`config.yaml` 的 `newest_keep`）。

## 在 Mac 上运行

**先申请 API Key（免费，2026 年 2 月起 OpenAlex 强制要求）**：到 https://openalex.org/settings/api 注册，复制 Key，在软件文件夹里执行（把 `你的Key` 换成真实的 Key）：

```bash
echo 你的Key > .openalex_key && chmod 600 .openalex_key
```

Key 只存在这个本地文件里（或环境变量 `OPENALEX_API_KEY`），**不要写进 config.yaml**，也不要发给别人；`.gitignore` 已排除它。

**再申请 Semantic Scholar API Key（免费，强烈建议）**：到 https://www.semanticscholar.org/product/api#api-key-form 填表申请，邮件收到 Key 后执行：

```bash
echo 你的S2Key > .s2_key && chmod 600 .s2_key
```

没有这个 Key 也能跑，但会和全球用户共享限额，经常被限速，第一次运行可能要几个小时。

```bash
cd ai4s_sourcing
python3 -m pip install -r requirements.txt
python3 run.py --quick     # 先试跑：每个领域只抓 200 篇（单独缓存，不影响正式数据），几分钟出结果
python3 run.py             # 全领域正式抓取
```

- **额度与续跑**：全领域跑一次约用 $0.7–0.9 的 OpenAlex 额度（有 Key 每天免费 $1）。如果当天额度用完，程序会自动停下、保存已抓完的领域，并先用已有数据生成结果；第二天再运行 `python3 run.py` 就会从没抓完的领域继续。
- **旧数据**：原来蛋白/抗体赛道抓的论文会自动沿用为「蛋白与核酸设计」领域的数据，不重复花额度。
- **只抓部分领域**：`python3 run.py --domains 药物发现,计算材料`
- **定期更新**：`python3 run.py --refresh all`（或只刷新某几个领域）
- **只重算不抓取**：`python3 run.py --skip-fetch`（改了分类关键词或评分后用，几秒钟，不耗额度）
- **领域和检索式**：都在 `config.yaml` 的 `fetch.domains`，可以自己增删改

结果在 `output/人才线索_*.xlsx`，主要工作表：

| 工作表 | 内容 |
|---|---|
| 新星榜 | 学术新星创业潜力榜：按主学科分领域排名，每人附新星分、四项分和理由 |
| 人才线索榜 | 按综合分排序，每人附分类标签、「推荐理由」、职业阶段、机构履历、代表作 |
| 机构榜 | AI4S 论文最多的机构（可发现新的"创始人工厂"） |
| 国家分布 | 各国人才数与 Top200 人数 |
| 赛道论文 | 筛选后的论文，含科学领域、AI方法、抓取来源领域，用于人工抽检 |
| 分类矩阵 / 类型×层级 | AI方法 × 科学领域的人数矩阵，人才类型 × 层级交叉表 |

## 可视化软件

数据跑完后，在终端执行：

```bash
python3 -m streamlit run app.py
```

浏览器会自动打开 http://localhost:8501 。以后也可以直接双击文件夹里的「启动可视化.command」。

| 页面 | 功能 |
|---|---|
| 🌍 全球地图 | 各国人才数 / 高潜人才数 / 平均分的世界地图，国家排行，职业阶段分布 |
| 🏆 人才线索榜 | 可排序、带进度条评分的线索表，左侧可按国家、阶段、方向、跟进状态等筛选，可导出 CSV |
| 👤 人才画像 | 个人评分、推荐理由、年度产出、机构轨迹、合作网络图、论文列表，**并可记录跟进状态和备注** |
| 🏛️ 机构 | 机构 Top 30（可只看企业），高潜人才聚集的机构 |
| 📈 方向趋势 | 各子方向年度论文数和增长率，用于寻找"学术升温"的窗口期 |
| 🚀 新星榜 | 学术新星创业潜力榜：分领域排名（二级/一级可切换）、各领域 Top N 总览、只看未接触的人、快速查看与导出 |
| ⭐ 团队收藏 | 全组共享的重点关注名单：按分组 / 收藏人筛选，点一行打开画像，可导出；在人才画像页和新星榜点「☆ 加入团队收藏」收藏，可写理由、分组。左侧栏可「只看团队收藏」 |
| 🧩 分类矩阵 | 「AI方法 × 科学领域」热力图，空格即人才空白；可切换人数 / 高潜 / 交叉型 / 已接触，点选格子看名单，可导出名单矩阵 |
| 📊 分类统计 | 人才类型、层级、关系强度、转化意向分布，交叉表，以及每个格子的人才结构与触达覆盖率 |

| 📝 修改动态 | 全组最近的跟进记录修改：谁、什么时候、把哪个字段从什么改成什么 |
| 👥 成员管理 | 仅管理员可见：添加成员、改角色、停用账号、重设密码 |

跟进记录保存在团队数据库 `team.db`，重新跑数据不会丢失；旧版的 `crm.csv` 会在第一次打开软件时自动导入（原文件改名为 `crm.csv.migrated` 备份）。

## 团队使用：登录与权限

第一次使用，先在终端里建一个管理员账号（会提示输入密码，至少 8 位）：

```bash
python3 manage_users.py add bill --name 比尔 --role admin
```

之后打开软件用这个账号登录，在「👥 成员管理」页给组员开账号。也可以继续用命令行：`passwd` 重设密码、`role` 改角色、`disable` / `enable` 停用或启用、`list` 查看全部（`python3 manage_users.py -h` 看帮助）。

| 角色 | 能做什么 |
|---|---|
| 管理员 | 全部功能，外加成员管理 |
| 编辑 | 查看全部数据，修改跟进记录和人工修正 |
| 只读 | 只能查看 |

- 每次保存都会记下修改人和时间，在人才画像页的「修改历史」和「📝 修改动态」页可查。
- 两个人同时编辑同一个人时，后保存的人会收到提示，而不会悄悄覆盖前一个人的修改。
- 密码加盐哈希存储（PBKDF2）；连续输错 5 次锁定 10 分钟。刷新浏览器页面需要重新登录。
- 只在自己电脑上单人使用时，可以在 `config.yaml` 里把 `auth.enabled` 改成 `false`。
- 局域网内共享：`python3 -m streamlit run app.py --server.address 0.0.0.0`，同事访问 `http://你的电脑IP:8501`。
- 需要备份的只有 `team.db`（跟进记录和账号）和 `.openalex_key`；其余数据都能重新生成。
- 部署到云服务器给全组用：见 [DEPLOY.md](DEPLOY.md)（含一键安装脚本 `deploy/setup.sh`、HTTPS、每周自动更新数据、每天自动备份）。

## 人才地图分类体系（config.yaml → taxonomy）

两个主维度决定一个人在地图上的位置，四个标签用于筛选和排优先级：

| 维度 / 标签 | 取值 | 来源 |
|---|---|---|
| 科学领域 | 一级 6 类、二级 16 类（生命科学与医学 / 化学与材料 / 物理 / 地球与宇宙 / 数学 / 通用（不限学科）） | 论文关键词，作者取最多的为主、第二多的为副 |
| AI方法 | ①科学基础模型 ②生成式设计 ③科学智能体与推理 ④自动化实验与具身 ⑤数学推理与形式化 ⑥数据、图学习与系统 ⑦可信与可解释；都不命中归 ⓪通用预测建模 | 同上 |
| 人才类型 | S 科学家 / A AI研究者 / A×S 交叉型 | AI 侧主题占比（优先用作者整个生涯的主题分布，没有时用赛道论文的领域和发表平台） |
| 层级 | 领军 / 资深 / 青年骨干 / 博士/博后 | 学术年龄 + h 指数 |
| 关系强度 | L1 共研/论文合作 / L2 有接触 / L3 未接触 | 人工，在「人才画像」页填写 |
| 转化意向 | 已创业 / 有意向 / 不确定 | 人工，在「人才画像」页填写 |

自动标签不准时，可以在「人才画像 → 跟进记录与人工修正」里改人才类型、层级、主学科、主方法，修正存进 `team.db`，重跑数据不会被覆盖。

改了关键词或门槛后，运行 `python3 run.py --skip-fetch` 即可用缓存数据几秒钟重算，不耗 API 额度。
如需按「整个学术生涯」判定人才类型（更准），运行一次 `python3 run.py --skip-fetch --refetch-profiles` 重新拉作者履历（约 20 个 API credits）。

## 赛道：AI4S 与通用 AI（config.yaml → tracks）

软件支持多个相互独立的人才库，左侧栏顶部可以切换：

| 赛道 | 运行命令 | 领域 |
|---|---|---|
| AI4S（默认） | `python3 run.py` | 16 个科学领域 × AI |
| 通用 AI | `python3 run.py --track general_ai` | 大模型训练与自进化、模型架构与基础模型、世界模型与空间智能、数据合成与评测、智能体与工具链、AI 系统与数据基础设施 |

- 每个赛道有自己的新星榜、矩阵、统计和 Excel（`output/人才线索_通用AI_*.xlsx`），结果分开存放，互不影响；
- 跟进记录、团队收藏、账号全赛道共享：同一个人在两个赛道里看到的是同一份跟进记录；
- 通用 AI 赛道用自己的「创始人工厂」名单（上海 AI Lab、MSRA、字节、月之暗面、清华、北大等），其余规则沿用默认赛道；
- 所有其他参数（`--quick`、`--refresh`、`--skip-fetch`、`--domains` 等）都可以和 `--track general_ai` 一起用；
- 想再加赛道：在 config.yaml 的 `tracks` 里照着 `general_ai` 写一段，只需写和默认赛道不同的部分。

## Semantic Scholar 补充数据源（config.yaml → s2）

OpenAlex 对 AI / 计算机方向、名字常见的中国学者识别很差：很多论文没挂作者号、被并到同名的人名下、超过 100 位作者的大团队论文只保留前 100 位。软件因此会接入 Semantic Scholar（S2）做三件事：

1. **补抓论文**：每个领域用同样的检索式在 S2 再抓「被引最高 2000 篇 + 近 6 个月最新 1000 篇」，补上 OpenAlex 漏掉的论文；
2. **修正作者归属**：用 DOI / arXiv 号把 OpenAlex 论文对到 S2，改用 S2 的完整作者列表和作者号（机构信息仍取自 OpenAlex）；
3. **合并同一个人**：同一 DBLP 消歧标识（如 "Kai Chen 0026"）或同一 ORCID 的多个 S2 作者号合并为一个人。

接入后大多数人的作者号会变成 `S2-数字`，以前按旧作者号记的跟进记录会自动对到新号上，不会丢。S2 的数据都缓存在 `data/s2/`，只有第一次运行要拉的量大，之后只补新的。不想用可以加 `--no-s2`，或在 config.yaml 把 `s2.enabled` 改成 `false`。

## 🎯 创业雷达（config.yaml → venture）

面向早期投资：结合近期成果，判断一位科学家出来创业的**成熟度**（时机）和**潜力**（价值），软件第一页。

| 维度 | 组成 |
|---|---|
| 创业成熟度 | 职业转折（博后末期 / 刚拿教职、近两年换机构尤其去企业）、独立带队（近 3 年首次以末位 / 通讯作者发表）、核心团队（3–15 位反复合作者）、产业合作上升、系统化产出（开源 / 工具 / 平台类成果） |
| 创业潜力 | 成果质量（近期主导论文在同年同领域的被引排位）、离产品距离（实验 / 临床 / 真实场景验证）、赛道窗口期（领域论文增长，OpenAlex 全量计数）、技术壁垒（自建数据 / 平台 / 基础模型） |

- 两项都是本赛道活跃学者中的百分位；两项都 ≥ 80 为「① 现在就该见」，其余为「② 技术好，继续跟踪」「③ 想创业，技术待验证」「④ 暂不关注」；
- 每个人都有**信号清单**：每条信号对应具体论文、年份、机构，可逐条核实；
- 每次更新数据后和上一次对比，列出**本周新出现信号的人**；
- 默认隐藏跟进记录里已创业或已投 / 在谈的人；
- Excel 里新增「创业雷达」表。

## 学术新星 · 创业潜力榜（config.yaml → rising_star）

面向投资：找近期冒头、有创业潜力的年轻学者，按领域分别排名。

- **谁算新星**：学术年龄 ≤ 12 年（以作者履历为准，只有首篇 AI4S 论文估算的不算）、不是领军人物、近 2 年 AI4S 论文 ≥ 2 篇且最近一年仍在发表。
- **新星分**（0–100，只在新星之间比较）＝ 影响力 40% + 势头 15% + 独立性 20% + 创业信号 25%
  - 影响力：本人主导（第一/末位/通讯作者）的最好 3 篇论文，在「同年、同领域」论文中的被引排位。新论文只和同年论文比，刚发表一两年的好论文不吃亏；挂名在大团队论文中间位置的不算主导
  - 势头：近期 AI4S 产出量和加速度
  - 独立性：近期末位/通讯作者论文数（正在成为独立 PI）和第一作者论文数
  - 创业信号：同下文
- 权重偏向影响力，防止只靠发文数量冲榜。所有门槛和权重都能在 config.yaml 里改，改完运行 `python3 run.py --skip-fetch` 即可。

## 评分逻辑（P0 启发式，全部可解释）

- **学术实力分**：赛道被引（对数）、h 指数、末位/通讯作者次数
- **增长势头分**：近 2 年产出、相对前 2 年的加速度
- **创业信号分**：产业合作占比、是否出身"创始人工厂"机构、近 2 年是否跳槽（尤其去企业）、是否处于创业高发阶段（学术年龄 5–14 年）
- **综合分** = 0.35 × 实力 + 0.35 × 势头 + 0.30 × 信号

## 可以调的地方（都在 config.yaml）

- `fetch.domains`：每个科学领域的检索式；`fetch.top_cited` / `fetch.recent`：每个领域抓多少篇
- `ai_terms`：AI 方法词（论文须命中其一，并属于 taxonomy 里某个科学领域，才进入人才库）
- `taxonomy`：分类体系（科学领域、AI方法关键词，人才类型、层级规则）
- `subtopics`：蛋白领域的细分子方向标签
- `feeder_institutions`：创始人工厂机构名单
- `mailto`：填邮箱可进入 OpenAlex 高速通道（可选）

## 已知局限（P1 解决）

1. 规则筛选会有误判 → 用「赛道论文」表人工标注约 2000 条，训练 SPECTER2 分类器
2. 创业信号是经验权重 → 匹配 Crunchbase/PitchBook 历史创始人，训练监督模型并回测
3. OpenAlex 作者消歧对常见中文/韩文姓名不完美 → 引入 ORCID 与合作者网络校正
4. 尚无工商注册、GitHub/Hugging Face、专利信号 → P2 接入
5. `feeder_institutions`（创始人工厂）名单目前只针对蛋白/生物药赛道，其他领域需要补充
